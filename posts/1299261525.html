发表于2024-07-20|更新于2024-09-09|web

注入攻击

注入攻击的本质，是把用户输入的数据当作代码执行，或者用于生成其他语义的内容。

注入攻击有两个前提条件：

1、用户能够控制数据的输入。

2、原本要执行的代码拼接了用户的输入。

SQL数据库类型判断

SQL常见数据库：

  • MySQL：开源、广泛使用，适用于各种应用场景，特别是Web应用。
  • PostgreSQL：开源，功能强大，支持复杂的查询和数据操作，适用于高要求的应用。
  • SQLite：轻量级，适合嵌入式系统和移动应用，通常用于小型项目或开发测试。
  • Microsoft SQL Server：由微软开发，功能丰富，适用于企业级应用。
  • Oracle Database：由Oracle公司提供，具有强大的企业级功能，适用于大规模和高性能的需求。
  • MariaDB：MySQL的一个分支，开源，致力于保持MySQL的兼容性，并提供额外的功能和改进。

预防措施

  1. 使用参数化查询：这是最有效的防护方法之一。通过预编译语句（ prepared statements）将SQL语句和数据分开，确保SQL语句不会因为输入数据的不同而改变。
  2. 输入验证和过滤：对用户的输入进行严格的校验和过滤，避免将未经处理的用户输入直接拼接到SQL语句中。可以通过正则表达式限制输入格式，或者对特殊字符进行转义处理。
  3. 使用ORM框架：对象关系映射（ORM）框架如MyBatis、Hibernate等通常内置了参数化查询和输入验证功能，能够减少SQL注入的风险。
  4. 存储过程：使用存储过程可以将复杂的SQL逻辑封装起来，并且每次调用存储过程时都需要提供参数，这样可以避免动态拼接SQL语句。
  5. 最小权限原则：确保数据库账户只拥有完成其任务所需的最低权限，这样即使发生SQL注入攻击，攻击者也无法执行更多的数据库操作。
  6. 安全的数据库连接：使用安全的数据库连接库，如PDO（PHP Data Objects），这些库提供了更多的安全特性来防止SQL注入。
  7. 避免动态拼接SQL语句：尽量避免在代码中动态拼接SQL语句，因为这增加了SQL注入的风险。如果必须使用动态SQL，应先进行严格的验证和过滤。
  8. 使用防火墙和入侵检测系统：通过防火墙和入侵检测系统监控和记录异常行为，及时发现并阻止潜在的SQL注入攻击。
  9. 定期审计和漏洞扫描：定期对应用程序进行安全审计和漏洞扫描，查找并修复可能存在的安全漏洞，以防止SQL注入攻击的发生。

SQL注入分类

SQL注入攻击是一种通过将恶意SQL代码插入到输入字段中以操控数据库的攻击方式。不同类型的SQL注入攻击针对不同的系统漏洞和输入处理方式。以下是SQL注入的常见分类及其特点：

1. Boolean（布尔注入）

特点：

  • 利用布尔表达式进行判断。
  • 通过在SQL查询中插入条件语句，观察返回页面的不同来推断数据库信息。

例子：

  • 如果返回的页面与正常请求相同，说明条件成立；否则不成立。

防御：

  • 使用参数化查询。
  • 验证和过滤输入。

2. Union（联合注入）

特点：

  • 使用UNION关键字将恶意查询与合法查询合并，以获取额外的数据。
  • 需要对目标表和恶意查询表的列数、数据类型进行匹配。

防御：

  • 使用参数化查询。
  • 限制或禁用数据库用户对UNION操作的权限。

3. Into Outfile（数据导出语句）

特点：

  • 利用INTO OUTFILE语句将数据库中的数据导出到服务器文件系统。
  • 需要有写文件的权限。

防御：

  • 限制数据库用户的文件写权限。
  • 使用安全的文件路径和名称。

4. Error（报错注入）

特点：

  • 通过构造错误的SQL语句，利用数据库返回的错误信息来推断数据库结构或数据。
  • 依赖于错误信息暴露的细节。

防御：

  • 不显示详细的数据库错误信息给用户。
  • 使用通用错误页面替代详细错误信息。

5. Blind SQL Injection（盲注）

6. 堆叠注入（Stacked Queries）

特点：

  • 应用程序允许一次执行多条SQL语句，通过分号;分隔。
  • 受到Web开发语言和数据库中间件的限制

例子：

防御：

  • 禁用多语句执行。
  • 使用参数化查询。

7. 二次注入（存储型注入）

特点：

  • 攻击者将恶意代码插入数据库中，稍后在应用程序从数据库中读取这些数据并执行时触发注入。
  • 通常涉及用户输入被存储后未进行适当的清理和验证。

例子：

  • 用户名字段存储了恶意SQL，在读取时被执行。

防御：

  • 在数据写入和读取时均进行过滤和验证。
  • 使用参数化查询。

8. 宽字节注入

特点：

  • 利用不正确的字符编码处理，特别是多字节字符集，如UTF-8。
  • 攻击者通过操控字符编码来绕过输入验证。

例子：

  • 在应用中输入%df%27，造成SQL语句中单引号被截断。

防御：

  • 正确处理字符集。
  • 在数据库连接时设置适当的字符集。

9. Regexp（正则表达式）

特点：

  • 利用SQL中的正则表达式匹配功能进行注入。
  • 可以用于构造复杂的条件语句。

例子：

  • 使用正则表达式构造恶意匹配条件。

防御：

  • 使用参数化查询。
  • 对正则表达式进行严格控制。

10. Header（HTTP头部注入）

特点：

  • 攻击者将恶意SQL注入到HTTP头部字段中，服务器端未对头部信息进行过滤时可能被执行。
  • 常见头部字段如User-Agent、Referer等。

例子：

  • 在User-Agent字段中插入SQL代码。

防御：

  • 对HTTP头部信息进行验证和过滤。
  • 使用参数化查询。

11. 万能密码

特点：

  • 使用特殊输入绕过认证机制。
  • 利用SQL注入使得任何密码均可通过验证。

例子：

  • 条件永远为真，允许攻击者登录。

防御：

  • 使用参数化查询。
  • 对用户输入进行严格的验证和过滤。

常见的MySQL注入点

  1. 用户输入表单：

    • 登录表单：攻击者可能在用户名或密码字段输入恶意SQL代码。
    • 注册表单：未正确验证和过滤的输入字段可能被用来插入恶意SQL。

  2. URL参数：

    • 动态生成的SQL查询中使用的GET参数，例如http://example.com/page?id=1，如果id参数未经过适当的处理，就可能成为注入点。

  3. 搜索框：

    • 搜索功能通常涉及动态SQL查询，未对用户输入进行适当过滤时容易受到攻击。

  4. Cookie和HTTP头：

    • 攻击者可以通过操控Cookie或HTTP头中的数据插入恶意SQL。

  5. 隐藏字段：

    • HTML表单中的隐藏字段可能被攻击者修改，用于注入SQL代码。

  6. 客户端输入的任何其他数据：

    • 例如Ajax请求、JSON或XML数据，如果直接用于SQL查询，则可能成为注入点。

  7. ORDER BY 或LIMIT参数：

    • 注意：不仅仅是在查询条件中，在SQL语句的ORDER BY 或LIMIT参数中也可能发生注入。比如，Web应用支持通过URL中的order参数来控制查询结果的排序，我们可以通过如下盲注方式来验证是否存在注入：

脱敏处理

数据脱敏是为了在开发、测试和分析中使用数据而不暴露敏感信息：

  • 隐藏重要信息：通过替换或屏蔽敏感数据的部分信息，使其无法被识别。例如：
    • 部分掩码：对于身份证号码、信用卡号，显示部分字符（如**** **** **** 1234）。
    • 伪数据：用虚拟数据替换真实数据。
  • 加密存储：对敏感数据进行加密，只有授权用户才能解密查看。
  • 数据匿名化：完全删除可识别个人身份的信息，确保无法逆向还原到个人。
