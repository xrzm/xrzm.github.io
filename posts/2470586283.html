OWASP_Top10之失效的身份认证

发表于2024-08-02|更新于2024-08-04|web漏洞

失效的身份认证

失效的身份认证漏洞（Broken Authentication）是指在应用程序的身份验证和会话管理过程中，由于设计或实现上的缺陷，攻击者能够破译密码、密钥或会话令牌，或者利用其他开发缺陷来冒充其他用户的身份。

这种漏洞通常会导致攻击者可以暂时性或永久性地冒充其他用户，从而破坏系统的安全性。

漏洞成因：

  1. 技术缺陷：身份验证机制本身存在弱点，无法有效防止暴力攻击。例如，密码过于简单或使用了不安全的哈希方法（如未加盐的MD5）来存储密码，这使得密码容易被破解。
  2. 逻辑缺陷和编码问题：在实现身份验证功能时，开发者可能会出现逻辑错误或编码不当，导致攻击者能够完全绕过身份验证机制。例如，某些系统可能没有正确处理会话令牌或密钥，或者在某些情况下允许未经授权的用户访问敏感资源。
  3. 用户行为：用户的行为也可能导致身份认证失效。例如，弱密码、重复使用默认密码等行为增加了被攻击的风险。此外，钓鱼攻击和社会工程学攻击也常利用用户的疏忽来获取凭证。
  4. 安全协议和配置错误：不安全的身份验证协议和配置错误也是常见原因。例如，单点登录（SSO）配置不当、基于CMS的访问漏洞、JWT令牌使用不当等都可能导致身份认证失效。
  5. 会话管理问题：错误使用应用程序的身份认证和会话管理功能，使攻击者能够破译密码、密钥或会话令牌，或者利用其他开发缺陷暂时或永久地冒充其他用户的身份。例如，服务器端生成的会话ID不够随机或熵低，容易被猜测或重放。
  6. 外部攻击：一些外部攻击手段如密码转储、字典攻击、撞库攻击等也会导致身份认证失效。这些攻击通常是在进行钓鱼或社会工程学攻击后发现的。

漏洞危害

恶意用户可能会窃取或操纵用户会话和cookie，进而模仿合法用户。
比如：

  • 窃取用户凭证和会话信息；
  • 冒充用户身份查看或者变更记录，甚至执行事务；
  • 访问未授权的页面和资源；执行超越权限操作

如何判断：

  1. 登录页面错误回显不一致：如果在Web网站的登录页面上，当输入错误的用户名或密码时，系统返回的信息不一致或者没有明确提示，这可能表明存在身份认证漏洞。
  2. 会话管理问题：攻击者可以利用应用程序的身份认证和会话管理功能的缺陷来窃取密码、密钥或会话令牌。例如，通过分析HTTP请求包，发现用户在登录后仍然能够访问受限资源，或者在未重新登录的情况下切换到其他用户的会话，这都可能是会话管理失效的表现。
  3. 密码破解和字典攻击：如果系统允许暴力破解或字典攻击，即允许多次尝试猜测密码，而不会锁定账户或采取其他安全措施，这也表明身份认证机制存在缺陷。
  4. 绕过机制：某些情况下，攻击者可以绕过身份验证机制，如通过修改请求包中的数据来绕过会话验证，或者利用系统漏洞直接获取会话令牌。
  5. 审计日志和监控：通过查看系统的审计日志和监控报告，可以发现异常登录行为或未授权访问事件。如果频繁出现此类事件，可能表明身份认证机制被绕过或失效。
  6. 第三方工具扫描：使用专业的漏洞扫描工具（如锐捷RG-SCAN）对系统进行全面扫描，可以发现潜在的身份认证漏洞，并进行相应的修复

防御措施：

区分公共区域和受限区域

  • 允许公共区域匿名访问，受限区域需身份验证。
  • 不同区域使用不同的身份验证和授权规则。
  • 避免在不必要的地方使用 SSL 以提升性能。

帐户锁定策略

  • 几次登录失败后禁用帐户或记录日志。
  • Windows 验证（如 NTLM 或 Kerberos）自动应用策略。
  • 表单验证需应用程序在设计阶段合并策略。
  • 预防服务攻击：使用自定义帐户名替代默认服务帐户。

验证 Cookie 内容

  • 通过加密和安全通信通道保护验证票证。
  • 身份验证 cookie 只通过 HTTPS 连接传输。
  • 使用 SSL 并对 cookie 内容加密，防止 XSS 攻击查看和修改 cookie。
  • 限制验证票证的有效期以防重复攻击。

零信任安全模型

  • 基于“零信任”原则，不再默认信任任何内部或外部网络请求，而是通过持续验证和最小权限原则来确保安全性。

多因素认证（MFA）

  • 多因素认证要求用户提供两种或以上的验证方式，如密码和手机短信验证码、指纹识别、动态口令等。这大大增加了攻击者成功入侵系统的难度。

会话管理与令牌策略

  • 确保会话令牌的不可预测性，并定期更新令牌以防止被猜测或爆破。例如，在使用JWT时，应始终执行算法验证，并固定签名算法在后端，不以JWT里的算法为标准。

加盐哈希和强密码策略

  • 采用加盐哈希方法来存储用户密码，避免使用简单的MD5哈希方法
  • 制定严格的密码策略，包括最小长度、复杂度要求及定期更换密码。
