Pickle反序列化漏洞详解

发表于2024-08-28|更新于2024-09-19|web

反序列化概念

序列化：将Python对象转换为字节流的过程。这个过程可以通过pickle.dump()或pickle.dumps()函数实现（两者的区别是写不写入文件）。

  • pickle.dump(obj, file)：将对象obj序列化并写入文件file。
  • pickle.dumps(obj)：将对象obj序列化为字节流并返回。

反序列化：将字节流转换回Python对象的过程。这个过程可以通过pickle.load()或pickle.loads()函数实现（两者的区别是从不从文件中读取）。

  • pickle.load(file)：从文件file中读取字节流并反序列化为Python对象。
  • pickle.loads(bytes_object)：将字节流bytes_object反序列化为Python对象。

可序列化的对象

  • None 、 True 和 False
  • 整数、浮点数、复数
  • str、byte、bytearray
  • 只包含可封存对象的集合，包括 tuple、list、set 和 dict
  • 定义在模块最外层的函数（使用 def 定义，lambda 函数则不可以）
  • 定义在模块最外层的内置函数
  • 定义在模块最外层的类
  • __dict__ 属性值或 __getstate__() 函数的返回值可以被序列化的类（详见官方文档的Pickling Class Instances）

__reduce__函数

pickle反序列化中的一个重要概念是__reduce__函数。__reduce__是一个特殊的方法，类似于PHP中的__wakeup()魔法函数，当一个对象被反序列化时，pickle会自动调用这个方法来决定如何重建对象。

__reduce__函数的作用

__reduce__方法的主要作用是告诉pickle在反序列化时应该做什么。具体来说，它返回一个元组，元组的第一个元素是一个可调用的对象，第二个元素是传递给该对象的参数。当pickle反序列化时，它会执行这个可调用对象，并传递相应的参数，从而重建对象。下面是一个简单的例子：

pickle过程解读

pickle解析依靠Pickle Virtual Machine (PVM)进行。

Pickle中的PVM（Pickle Virtual Machine）是Python中的一个虚拟机，专门用于序列化和反序列化Python对象。PVM是Python标准库中的一部分，由Python的pickle模块提供支持。它的主要功能是从流中读取opcode（操作码）和参数，并对其进行解释处理，从而实现对象的序列化和反序列化。

而PVM涉及到三个部分： 指令处理器、 栈 、内存

  1. 指令处理器：这是PVM的核心部分，负责从流中读取opcode（操作码）和参数，并对其进行解释处理。这个过程是重复进行的，直到流结束为止（也就是遇到.时才会停止）。
  2. 栈：栈是PVM中的一个重要组成部分，用于存储和操作数据。它类似于一个典型的栈结构，通常实现为一个列表。
  3. Memo：Memo是PVM中的另一个重要元素，用于存储已经处理过的对象，以便在后续处理中可以快速访问和引用这些对象。

opcode简介

在Python的pickle模块中，opcode（操作码）是指在序列化和反序列化过程中使用的一系列指令代码。这些操作码用于表示和处理Python对象的类型和值，确保对象能够被正确地序列化到文件或网络流中，并在需要时反序列化回原始对象。

opcode类似于一种独立的语言，通过对这些操作码的编写，可以执行Python代码、覆盖变量等操作。直接编写的操作码比使用pickle序列化生成的代码更具灵活性。

注意：部分Linux系统下和Windows下的opcode字节流并不兼容，比如Windows下执行系统命令函数为os.system()，在部分Linux下则为posix.system()

opcode版本

pickle由于有不同的实现版本，在py3和py2中得到的opcode不相同。但是pickle可以向下兼容（所以用v0就可以在所有版本中执行）。目前，pickle有6种版本。

在 pickle 的序列化和反序列化过程中，各种 opcode 执行特定操作并在栈上进行数据处理。具体而言，TRUE 可以用 b'I01\n' 表示，而 FALSE 用 b'I00\n' 表示。其他 opcode 的详细信息可以参见 pickle库的源代码。

以下是一些关键点：

  1. 栈操作：

    • 在 pickle 中，数据以栈的形式进行操作。每种 opcode 执行特定的任务，按照一定顺序在栈上处理数据。理解这些操作码时，需设想栈中的数据状态，以便正确理解和使用每种操作码。

  2. 与 Python 操作的对照：

    • 对照 Python 操作，pickle 中的某些 opcode 与 Python 的操作对应。例如，a 对应 Python 列表的 append，e 对应 extend；字典的 update 对应 u。

  3. 操作码功能：

    • c 操作码尝试 import 库，因此在 pickle.loads 过程中无需在漏洞代码中提前引入系统库。

      其中 c 操作码指向的实际上是一个 self.find_class(modname, name); 可以在源码中找到

    • s、u 和 b 操作码允许构造并赋值新的属性或键值对，而不需要预先定义这些属性或键值对。

    • pickle 不允许使用列表索引、字典索引或点号（属性访问）作为赋值目标（左值）。赋值操作必须通过函数如 getattr 或 dict.get 来实现。

  4. 右值与左值：

    • 右值：用于读取或查找值。在 pickle 中，s、u 和 b 操作码用于读取值。
    • 左值：用于赋值。pickle 不允许直接使用索引或点号操作符作为左值。

  5. 栈操作的辅助 opcode：

    • p、q、r 操作码将栈顶元素存入 memo（临时内存），并用索引进行区分。g、h、j 操作码则从 memo 中根据索引将元素推回栈顶。这些 opcode 主要用于弹出或修改非栈顶元素时，将栈顶元素临时保存。

  6. 常用 opcode：

    • R 由特殊方法 reduce 生成，对栈顶的 tuple 进行 callable 操作，第一个元素为可调用对象（通常由 c 获取），第二个元素为参数 tuple。
    • i 和 o 均用于创建类的实例或调用方法，但它们的参数传递方式不同。i 接收 modname 和 name 两个参数，用于创建实例或调用方法，栈内的内容在使用 i 时标识为数据开始。

opcode分析

pickletools可以方便的将opcode转化为便于肉眼读取的形式

这段 pickle 序列化的数据是 Python 序列化协议（Protocol 3）的具体字节流表现。每个字节码有对应的操作符或指令，下面对每一行进行详细解释：

  1. \x80 PROTO 3
  • \x80: 这是 PROTO 操作符，表示 pickle 的协议版本。
  • 3: 协议版本号。这里表示使用了 Pickle 协议版本 3（用于 Python 3.x 及其以上版本）。
  1. c GLOBAL 'nt system'
  • c: GLOBAL 操作符。GLOBAL 用于引用一个模块中的全局函数或类。
  • ‘nt system’: 这是 os.system，其中 nt 是指 Windows 平台上的 os 模块，包含的 system 方法用于执行系统命令（nt 是 os 模块的一部分，对应于 Windows）。如果在 Linux 下，此处可能会显示 'posix system'。
  1. q\x00 BINPUT 0
  • q: BINPUT 操作符，表示将下一个对象存储在一个位置，供后续引用（类似于为对象创建索引）。
  • \x00: 这个字节表示要将对象存储在位置 0（这是一个内存位置标识符）。存储在位置 0 的对象是前面的 os.system。
  1. X BINUNICODE 'echo "Exploit executed"'
  • X: BINUNICODE 操作符，表示下一个是一个 Unicode 字符串，紧随其后的数字是字符串的长度。
  • 17: 这个数字表示字符串的长度为 23 个字节（Unicode 长度）。
  • ‘echo “Exploit executed”‘: 这是要传递给 os.system 的参数，即系统命令 echo "Exploit executed"。这个命令将在终端上打印 "Exploit executed"。
  1. q\x01 BINPUT 1
  • q: 这是 BINPUT 操作符，用于将下一个对象存储在位置 1，供后续引用。
  • \x01: 存储位置 1 的对象是 echo "Exploit executed" 这个字符串。
  1. \x85 TUPLE1
  • \x85: TUPLE1 操作符，表示从栈中弹出一个对象，并将其打包成单元素元组。
  • TUPLE1: 这里的 TUPLE1 作用是将栈顶的对象（echo "Exploit executed"）打包为一个元组。这一步的结果是创建了一个单元素的元组 ('echo "Exploit executed"',)。
  1. q\x02 BINPUT 2
  • q: 这是 BINPUT 操作符，用于将下一个对象存储在位置 2。
  • \x02: 存储在位置 2 的对象是刚才生成的元组 ('echo "Exploit executed"',)。
  1. R REDUCE
  • R: REDUCE 操作符，表示从栈中弹出两个对象，第一个是一个可调用的对象（在此例中是 os.system），第二个是参数（('echo "Exploit executed"',)），然后将它们组合并调用该函数。
  • REDUCE: 这一步会应用 os.system('echo "Exploit executed"')，即执行系统命令，打印 "Exploit executed"。
  1. q\x03 BINPUT 3
  • q: BINPUT 操作符，表示将下一个对象存储在位置 3。
  • \x03: 存储位置 3 的对象是刚刚执行的结果。
  1. STOP .
  • .: STOP 操作符，表示序列化过程结束。

思路一：getattr()

理清思路

getattr(object, name[, default]) 的基本功能是从 object 中获取名为 name 的属性。

动态特性：

  1. 动态属性访问： getattr 允许程序在运行时决定要访问的属性名，而不是在编写代码时就固定。
  2. 安全绕过： 动态特性使得 getattr 可以绕过某些静态检查或限制。例如，在一个受限环境中，某些属性或方法可能被列入黑名单，但攻击者可以通过 getattr 动态访问这些方法。

1、和SSTI、沙箱逃逸的思路类似（通过构造类对象链调用某些方法中含有危险函数的类实现绕过），这段代码中没有禁用内置的getattr()函数，而getattr()函数可以获取对象的属性值，因此我们可以通过builtins.getattr(builtins,'eval')的形式来获取eval函数

在示例函数中的RestrictedUnpickler类，含有restricted_loads方法，其中restricted_loads是一个类似于pickle_loads的一个函数，所以我们可以构造pickle_loads进行代码执行，而不是通过具有限制的restricted_loads来执行代码

2、值得注意的是，由于pickle.loads()的参数需要为byte类型（字节流）。而在Protocol 0中，对于byte类型并没有很好的支持，需要额外导入encode()函数，可能会导致无法绕过find_class限制。

3、直到Protocol 3版本，Python才引入了B和C两个字节码来标识byte类型

  • B（BINBYTES）：用于表示普通的字节串，它可以处理长度不受限制的字节串。
  • C（SHORT_BINBYTES）：用于表示较短的字节串（长度小于256字节）。

可以看到此时pickle对于byte类型变量的支持精简了很多。所以当我们想利用pickle.loads()来绕过find_class时，最好选择Protocol 3版本的opcode构造。

绕过R过滤（i、o、b）

  1. i字节码：相当于c和o的组合，先获取一个全局函数，然后寻找栈中的上一个MARK，并组合之间的数据为元组，以该元组为参数执行全局函数（或实例化一个对象）

  2. o字节码：寻找栈中的上一个MARK，以之间的第一个数据（必须为函数）为callable，第二个到第n个数据为参数，执行该函数（或实例化一个对象）

  3. b字节码：用于执行__dict__.update()操作，通常用于更新对象的属性。当PVM解析到b指令时执行__setstate__或者__dict__.update()

b操作码对应的是load_build函数; 使用栈中的第一个元素（储存多个属性名: 属性值的字典）对第二个元素（对象实例）进行属性设置

那什么是__setstate__呢？官方文档中，如果想要存储对象的状态，就可以使用__getstat__和__setstat__方法。由于pickle同样可以存储对象属性的状态，所以这两个魔术方法主要是针对那些不可被序列化的状态，如一个被打开的文件句柄open(file,'r')。

1、我们来看下面的例子：

当对象被序列化时调用__getstate__，被反序列化时调用__setstate__。重写时可以省略__setstate__，但__getstate__必须返回一个字典。如果__getstate__与__setstate__都被省略, 那么就默认自动保存和加载对象的属性字典__dict__

2、那么这里就会出现一个问题：如果我们将字典{"__setstate__":os.system}，压入栈中，并执行b字节码，由于此时并没有__setstate__，所以这里b字节码相当于执行了__dict__.update，向对象的属性字典中添加了一对新的键值对。

如果我们继续向栈中压入命令command，再次执行b字节码时，由于已经有了__setstate__，所以会将栈中字节码b的前一个元素当作state，执行__setstate__(state)，也就是os.system(command)。
